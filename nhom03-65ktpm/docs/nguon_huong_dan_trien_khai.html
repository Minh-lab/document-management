2. Clone và chạy dự án

1Clone mã nguồn

git clone https://github.com/Minh-lab/document-management.git
cd document-management/code

2Cài dependencies

flutter pub get

3Kiểm tra cấu hình dùng chung (không cần sửa)

TệpNội dung
lib/config/supabase_config.dartURL + publishable key của Supabase
lib/firebase_options.dartCấu hình Firebase cho Android và Web
android/app/google-services.jsonĐịnh danh app Android com.example.code
Không tạo Firebase/Supabase mới Nhóm dùng chung một project. Nếu bạn tạo project riêng, app sẽ không thấy dữ liệu của nhóm và mọi thay đổi schema sẽ lệch. Cần quyền xem dashboard thì liên hệ Minh để được thêm vào tổ chức.

4Chạy ứng dụng

flutter devices                 # xem danh sách thiết bị
flutter run -d chrome           # Web
flutter run -d <device-id>      # Android (emulator hoặc máy thật)

5Cập nhật code mới nhất mỗi ngày

git checkout main
git pull origin main
flutter pub get

Build bản phát hành

flutter build apk --release      # build/app/outputs/flutter-apk/app-release.apk
flutter build web --release      # build/web/

3. Checklist công việc

3.1. Checklist cá nhân (làm xong trước khi nhận việc)

  • Clone được repo và chạy app trên Chrome không lỗi
  • Chạy được trên Android (emulator hoặc máy thật)
  • Đăng nhập thành công, thấy danh mục mặc định
  • Thêm, sửa, xóa được một tài liệu thử nghiệm
  • Biết tạo nhánh, commit, push và mở Pull Request

3.2. Checklist theo hạng mục dự án

#Hạng mụcTiêu chí hoàn thành
1Kiến trúc hệ thống và mô hình dữ liệu Firebase (Auth/Messaging) + Supabase (DB/Storage)Có sơ đồ kiến trúc; schema và RLS chạy trên Supabase; tài liệu mô tả bảng và luồng dữ liệu
2Giao diện Flutter đa nền tảng, responsive Mobile và WebChạy tốt ở 360px, 768px, 1440px; không lỗi overflow; có ảnh chụp 3 breakpoint
3Phân loại tài liệu bằng Tag và quản lý vị trí vật lýGán và lọc được nhiều tag; lưu và mở lại được vị trí; bản đồ hiển thị trên Android và Web
4Luồng yêu cầu mượn và chia sẻ quyền truy cậpChạy trọn vòng: gửi yêu cầu → duyệt → mở tài liệu → trả; người ngoài không thấy dữ liệu
5Thuật toán Recommendation theo sở thích/tagCó khối "Gợi ý cho bạn" kèm lý do; xử lý được người dùng mới; phản hồi dưới 300ms
6Kiểm thử toàn diện và đóng gói sản phẩmTest pass trên CI; có báo cáo kiểm thử; build được APK và bản Web

3.3. Checklist trước khi nộp

  • flutter analyze không có lỗi, flutter test pass toàn bộ
  • Ứng dụng chạy ổn định trên cả Android và Web
  • Đã cập nhật tài liệu: kiến trúc, kiểm thử, hướng dẫn sử dụng
  • Có APK release và bản Web build
  • Tag phiên bản v1.0.0 trên GitHub, main sạch

5. Quy trình làm việc

5.1. Git

git checkout main && git pull origin main
git checkout -b feature/<ten>-<viec>
# ... code ...
git add . && git commit -m "feat: mô tả thay đổi"
git push -u origin feature/<ten>-<viec>
  • Không push trực tiếp lên main; mọi thay đổi đi qua Pull Request và cần ít nhất một người review.
  • Trước khi mở PR: flutter analyze, flutter test, chạy thử trên Chrome.
  • Commit theo mẫu: feat:, fix:, docs:, test:, refactor:, chore:.

5.2. Bảo mật

  • Không đưa service_role key, JWT secret hay service account JSON lên Git.
  • Không tự sửa policy trên Supabase; đề xuất qua Minh để review chéo.
  • Không commit thư mục build/, .dart_tool/, .idea/.
